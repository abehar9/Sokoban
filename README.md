Sokoban – PDDL-Based Solver
Overview

This project implements an automated solver for the classic Sokoban puzzle game using PDDL (Planning Domain Definition Language) and Java.

Sokoban is a puzzle game in which a player must push boxes across a grid to designated target locations. The player can move up, down, left, and right, but can only push boxes and cannot pull them. The objective is to place all boxes on the target positions.

The goal of this project is to represent the Sokoban game as an AI planning problem, generate PDDL problem instances from game levels, and use a PDDL planner to find a sequence of actions that solves the puzzle.

Original Repository

This project is based on the original Sokoban implementation:

https://github.com/fiorinoh/sokoban/tree/master

The original repository provides the Sokoban game environment and level configurations. The project extends this implementation by introducing PDDL-based planning and integrating a solver to automatically generate solutions.

Files Created or Modified

The following files were created or modified as part of this project:

1. PDDLProblemGenerator.java

Responsible for generating PDDL problem files from the Sokoban game levels.

Its main purpose is to translate the board configuration into a representation that can be understood by a PDDL planner. This includes identifying the relevant elements of the board, such as:

The available positions on the board.
The walls and valid movement connections.
The initial position of the player.
The initial positions of the boxes.
The target locations.
The goal conditions that must be satisfied.

This class bridges the original Sokoban game representation and the PDDL planning environment.

2. Agent.java

Responsible for connecting the planning solution with the Sokoban game environment.

The agent executes the actions generated by the planner within the game. It translates the solution into movements that the Sokoban interface can understand, allowing the player to follow the calculated sequence of actions.

This class is responsible for integrating the automated planning process with the actual game execution.

3. SokobanSolver.java

Responsible for solving the generated Sokoban planning problem.

This class integrates the PDDL planning process and coordinates the execution of the planner. It uses the generated problem representation together with the Sokoban domain to obtain a valid sequence of actions.

The resulting plan represents the movements required to move the boxes onto their target locations while respecting the rules of the game.

4. Sokoaban.pddl (Domain)

Defines the Sokoban domain using the Planning Domain Definition Language (PDDL).

It describes the rules and possible actions of the game, including:

The predicates used to represent the game state.
The conditions required for an action to be executed.
The effects of each action on the game state.
The movement of the player.
The pushing of boxes.
The conditions that must be satisfied to complete the puzzle.

The domain defines the general rules of Sokoban independently of any specific level. Individual puzzle configurations are represented separately through generated PDDL problem files.

Project Workflow

The overall solving process follows these steps:

Level Input: A Sokoban level is loaded from the original game environment.
Problem Generation: PDDLProblemGenerator.java translates the level configuration into a PDDL problem representation.
Planning: SokobanSolver.java uses the PDDL domain and generated problem to invoke the planner and calculate a solution.
Solution Execution: Agent.java receives the generated plan and executes the corresponding movements in the Sokoban game.
Puzzle Completion: The puzzle is solved when all boxes have been placed on their respective target locations.
Technologies Used
Java – Implementation of the problem generator, solver, and agent.
PDDL – Representation of the Sokoban domain and planning problems.
PDDL4J – Java planning library used to integrate automated planning.
Sokoban – Original game environment and level configurations.

Maven is needed.

Install pddl4j (https://github.com/pellierd/pddl4j) in your local maven repo:
```
mvn install:install-file \
   -Dfile=<path-to-file-pddl4j-4.0.0.jar> \
   -DgroupId=fr.uga \
   -DartifactId=pddl4j \
   -Dversion=4.0.0 \
   -Dpackaging=jar \
   -DgeneratePom=true
 ```  
Work with maven: mvn clean, mvn compile, mvn test, mvn package

Run with: 
````
java --add-opens java.base/java.lang=ALL-UNNAMED \
      -server -Xms2048m -Xmx2048m \
      -cp "$(mvn dependency:build-classpath -Dmdep.outputFile=/dev/stdout -q):target/test-classes/:target/classes" \
      sokoban.SokobanMain
````
or (after mvn package)
```
java --add-opens java.base/java.lang=ALL-UNNAMED \
      -server -Xms2048m -Xmx2048m \
      -cp target/sokoban-1.0-SNAPSHOT-jar-with-dependencies.jar \
      sokoban.SokobanMain
```
